## 一、记忆层：投毒隔离与过期折叠

### 方法

构造六类记忆存储状态，对照"直接使用原存储"与"经修复层处理"：

| # | 样本 | 故障 |
|---|---|---|
| 1 | 干净 | 无 |
| 2 | 投毒-不可信来源 | 来源不在白名单内 |
| 3 | 投毒-注入特征 | 内容含指令注入模式（"忽略之前的指令"等） |
| 4 | 过期-同键旧条目 | 同一语义键上有更新的条目，旧条目仍live |
| 5 | 组合-投毒+过期 | 上述两类同时出现 |
| 6 | 全部可疑 | 存储中仅有可疑条目 |

判定口径：
- **不修复可用** = 存储本身无缺陷（可直接参与检索）
- **修复后可用** = 修复状态符合预期，**且**复检无剩余缺陷，**且**良性可用条目未减少

### 结果

| 样本 | 不修复可用 | 修复后可用 | 修复动作 |
|---|---|---|---|
| 干净 | 是 | 是 | 无（ok） |
| 投毒-不可信来源 | 否 | 是 | 隔离该条目 |
| 投毒-注入特征 | 否 | 是 | 隔离该条目 |
| 过期-同键旧条目 | 否 | 是 | 标记为已被新条目取代（折叠） |
| 组合 | 否 | 是 | 隔离 + 折叠 |
| 全部可疑 | 否 | 是 | **拒绝执行** |
| **合计（6 例）** | **1（17%）** | **6（100%）** | — |

### 两条设计结论

**1. 折叠必须改变状态，不能只留记录。**
初版实现只追加一条折叠记录，条目状态不变；复检时旧条目**仍被判定为过期**，
于是"修好了"这一断言无法通过验证。修正为把旧条目标记 `superseded_by`（不再参与检索），
记录与状态才一致。**这条是靠复检机制自己暴露出来的**，不是靠人工检查。

**2. 全部可疑时拒绝，而不是清空。**
若隔离所有可疑条目会让存储为空，本层明确拒绝。理由是两种损失不对等：
- 保留可疑条目 = 可撤销的污染（回滚即可恢复）
- 清空记忆 = 不可逆的损失

即使"清空"在数值上能让缺陷归零，也不执行。

### 回滚

隔离与折叠都记录时间戳，可撤销某个时间点之后的操作。本层不做物理删除，
故回滚只需复位状态位，无需恢复数据。

## 二、计划层：停滞检测与重规划触发

### 方法

构造五类执行轨迹，对照"继续按原计划执行"与"经修复层给出升级指令"：

| # | 轨迹 | 预期 |
|---|---|---|
| 1 | 正常（全部成功） | 无信号 |
| 2 | 停滞 + 有成功步 + 有备选动作 | 重规划 |
| 3 | 停滞 + 有成功步 + 无备选动作 | **拒绝** |
| 4 | 循环（相同动作与观察重复） | 升级 |
| 5 | 预算耗尽且全程无成功 | 升级 |

判定口径：
- **不修复可用** = 无停滞信号（计划可继续执行）
- **修复后可用** = 给出可执行指令（经 `verify_directive`），或对不可执行的情形正确拒绝

### 结果

| 轨迹 | 不修复可用 | 修复后可用 | 指令 |
|---|---|---|---|
| 正常 | 是 | 是 | 无（ok） |
| 停滞-可重规划 | 否 | 是 | `replan`（从最近成功步恢复） |
| 停滞-无备选 | 否 | 是 | **拒绝**（重规划会给出与失败时相同的动作） |
| 循环 | 否 | 是 | `escalate`（原路重规划无效） |
| 预算耗尽 | 否 | 是 | `escalate`（升档或转人工） |
| **合计（5 例）** | **1（20%）** | **5（100%）** | — |

### 两条设计结论

**1. 指令必须过可执行性校验，否则等于没修。**
`replan` 要求 `resume_from` 指向真实成功步**且**备选动作非空。缺任一条，
该指令会产生与失败时完全相同的动作——那是空操作，不是修复。此时明确拒绝。

**2. 循环与停滞需要不同的升级动作。**
两类信号看着相似，但对策相反：
- **停滞**（连续失败，观察各异）→ 有成功步可回退，重规划有效
- **循环**（相同动作与观察重复）→ 原路重规划必然再次进入循环，必须换策略或升档（`escalate`）

另有一类需要区分：**停滞且全程无成功步**。此时没有可靠恢复点，重规划无从下手，
正确动作是升级（`escalate`）而不是拒绝——拒绝应当留给"有恢复点但没有备选"那种真正的空操作。

## 四、口径与局限

- **样本为自建**：11 例覆盖设计内的故障类型，不构成对真实流量的覆盖率估计。
  本轮即出现一次"自建样本与预期不符"的情形（初版停滞用例的动作与观察相同，
  被正确判为循环而非停滞）——说明**样本本身的构造需要与检测器的语义对齐**。
- **两张表都是"缺陷是否被处理"的口径，不是"下游任务是否成功"**。修复层保证的是
  存储/计划状态的正确性，不保证端到端任务完成。
- **记忆层的可信来源白名单与注入特征表为示例规模**，生产需替换为实际来源体系与规则库；
  当前实现不检测"语义正确但来源可信"的错误记忆（那属于诊断问题，不在本层）。
- **计划层的阈值**（连续失败窗口 3、循环重复 2 次）为启发式初值，未做大样本调参。
- **回滚的粒度是时间点**，不支持按算子类型选择性回滚。
- 代码层与 Harness 层（第 6、7 层）**未实现**，本轮未触及。
